# Cadabra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Cadabra, a Fire TV party game where the room describes a game and an AI agent on Bedrock builds a playable 2D multiplayer game in ≤ 30 s, with phones as controllers.

**Architecture:**
- **TV side.** A Kotlin Fire TV shell hosts a WebView. The WebView loads a bundled TypeScript TV app with Preact screens and a PixiJS renderer. That app runs the authoritative headless game engine.
- **Phones.** Phones load an HTTPS controller from CloudFront. They signal through an API Gateway WebSocket and then talk to the TV over a direct WebRTC DataChannel, with a relay fallback.
- **Backend.** A CDK-deployed backend (Lambda, DynamoDB, S3/CloudFront) runs the "Forge". The Forge is a Claude tool-calling agent that drafts, validates and bot-playtests game specs using the same engine package. It also handles Nova Canvas art, Polly host audio, Guardrails and the Arcade.

**Tech Stack:**
- TypeScript 5, npm workspaces, Vitest, zod 3, PixiJS 8, Preact 10, Vite 6, quickjs-emscripten.
- Android: Kotlin, AGP 8, minSdk 28, androidx.webkit.
- AWS: CDK v2 (TypeScript), AWS SDK JS v3. Bedrock Converse API (Claude Sonnet 5.5 / Haiku 5.5), Nova Canvas, Polly, Bedrock Guardrails. API Gateway WebSocket, Lambda (Node.js latest), DynamoDB, S3, CloudFront.

**Spec:** `docs/superpowers/specs/2026-10-20-cadabra-design.md`

**Product rules from the spec**
- English only: UI, generated games, host voice.
- 2D only. Fire OS only (no Vega).
- The look is "Direction A, Cinematic (PS5-inspired)":
  - full-bleed key art,
  - a big display title on the left,
  - a bottom tile row whose focused tile is enlarged and outlined,
  - per-game palette re-tinting.
- Fonts are Bricolage Grotesque (display) and Figtree (UI). Both are bundled locally; there is no CDN on the TV.
- 10-foot rules: body text ≥ 28 px at 1080p; 5% title-safe margins; focus always visible; every TV screen fully usable with D-pad, Select, Back and Play/Pause.
- Players: 2–8 plus bots. Bots fill up to 4 with "Fill with bots". Rounds last 60–120 s.
- Idea Storm lasts 20 s. Each game has a mid-round surprise event and a final-10-s twist.

**Performance and timing budgets**
- Forge ≤ 30 s from vote close to a playable game.
- Light pitches arrive ≤ 8 s after the Idea Storm ends.
- AI remix ≤ 10 s. Tweak-panel changes apply instantly.
- Frame rate: target 60 fps on the stick, never below 30 fps during play. Internal render resolution 1280×720, upscaled.
- Input latency < 50 ms phone→TV over direct WebRTC on the same Wi-Fi.

**Content and safety**
- No copyrighted audio. SFX are generated in code (jsfxr-style); music is procedural or none.
- Family-safe mode is on by default. It applies Bedrock Guardrails to player inputs and to generated text and image prompts.
- Selfies are deleted after the avatar is generated.
- No personal data in URLs. Share codes expose only the spec and art.
- Every network or AI failure has an in-game fallback. The room never sees an error screen.

**Infrastructure**
- AWS region `ap-south-1` for everything except Nova Canvas, which uses `us-east-1`. AWS account `380794909728`.
- No AWS credentials ever on the TV or phones.

## Review Focus

These are failure modes the spec implies but that no task's tests exercise by default. Each line has an owning test added in the named task.

1. **A phone disconnects mid-round** (Wi-Fi blip, screen lock), then reopens the link.
   - Expected: they rejoin as the same player with their score.
   - Their avatar idles while they're gone; the round never stalls.
   - Test: Task 10 (`rejoin keeps playerId`), Task 4 (`missing input does not stall`).
2. **A player joins during Forge or Play.**
   - Expected: they become a spectator for that round and join at the next round. No crash; no spec re-roll.
   - Test: Task 12 (`late join becomes spectator`).
3. **The Bedrock agent times out, returns malformed JSON, or fails every playtest.**
   - Expected: the Forge falls back to a prebuilt kit game themed from the ingredients, within budget, and the host makes a joke.
   - Test: Task 16 (`forge falls back when agent fails`).
4. **Offensive ingredient or remix text while family-safe is on.**
   - Expected: it is silently dropped from the board; the player sees "Try another idea" on their phone, and nothing reaches generation.
   - Test: Task 14 (`blocked input never reaches designer`).
5. **8 players plus particles on the stick.**
   - Expected: frame rate stays ≥ 30 fps, with particle caps and effect degradation kicking in automatically.
   - Test: Task 8 (`fx budget caps particles`) plus the on-device check in Task 13.

```ts
export interface Entity { id: number; kind: string; x: number; y: number; vx: number; vy: number; r: number; sprite: string; owner?: string; team?: 0|1; tags: Set<string>; props: Record<string, number|string|boolean> }

export type FxEvent = { kind: 'particles'; preset: 'sparkle'|'smoke'|'burst'|'splash'|'confetti'; x: number; y: number } | { kind: 'shake'; strength: number } | { kind: 'flash'; color: string } | { kind: 'sfx'; name: string } | { kind: 'slowmo'; ms: number } | { kind: 'banner'; text: string };
export interface GameEvent { t: number; type: string; player?: string; data?: Record<string, unknown> } // feeds host roast + results
export interface BlockCtx<P> { params: P; world: World; players: Player[]; rng: Rng; time: number; remaining: number;
  score(playerId: string, delta: number, reason: string): void; emit(e: Omit<GameEvent,'t'>): void; fx(e: FxEvent): void;
  eliminate(playerId: string): void; entityOf(playerId: string): Entity | undefined; }
export interface BlockDef<P = any> { id: string; name: string; summary: string; paramsSchema: z.ZodType<P>; defaults: P;
  controls: ControlWidget['kind'][]; arenaKinds: GameSpec['arena']['kind'][];
  setup(ctx: BlockCtx<P>): void; update(ctx: BlockCtx<P>, dt: number): void;
  onInput(ctx: BlockCtx<P>, playerId: string, input: InputFrame): void; bot(ctx: BlockCtx<P>, playerId: string, skill: number): InputFrame;
  onTimeline?(ctx: BlockCtx<P>, ev: TimelineEvent): void; }
export class BlockRegistry { register(def: BlockDef): void; get(id: string): BlockDef | undefined; list(): BlockDef[] }
export class GameRuntime {
  constructor(spec: GameSpec, players: Player[], registry: BlockRegistry, seed: number);
  input(playerId: string, frame: InputFrame): void; step(): void; // fixed dt = 1/60
  get state(): 'intro'|'playing'|'finale'|'over'; get time(): number;
  snapshot(): { entities: Entity[]; players: Player[]; time: number; remaining: number; banner?: string };
  drainFx(): FxEvent[]; get events(): GameEvent[]; result(): { ranking: Player[]; winnerTeam?: 0|1; events: GameEvent[] };
  applyParams(blockIndex: number, patch: Record<string, unknown>): void; // Tweak panel, live
}
```

Runtime rules:
- Order of operations:
  1. Validate each block's params with `paramsSchema.parse({...defaults, ...use.params})`.
  2. Run the blocks' `setup` in spec order.
  3. Each step: deliver the latest inputs, then call `update` on every block.
- Timeline events fire once their `atSec` passes. Each one calls `onTimeline` and raises the host banner `ev.hostLine`.
- The final 10 s sets `state='finale'` and emits `{type:'finale'}`.
- Comeback: every 5 s, the last-place player(s) get `props.boost = 1 + 0.15*strength`. Blocks read `boost` when they compute speed.
- Win: as configured in `spec.win`.
- A missing or stale input (older than 500 ms) counts as zero input. The game never waits for one.
